# Consistency-Gated RAG

A **Retrieval-Augmented Generation** system that only triggers document retrieval when the LLM is uncertain about its answer. Rather than always paying the latency and cost of a RAG pipeline, the system uses **self-consistency** as a proxy for model confidence to decide whether retrieval is actually needed.

---

## Motivation

Standard RAG systems retrieve documents on every query regardless of whether the model already knows the answer. This introduces unnecessary latency and API cost for questions the model can answer confidently from its parametric knowledge (e.g. *"What is the capital of France?"*).

This project implements a **consistency gate**: the model answers the same question multiple times, and the semantic agreement between those answers is used as a confidence signal. Only when the model is uncertain (i.e. answers diverge) does the system fall back to grounded retrieval.

This approach falls under the broader paradigm of **agent-based RAG**, where the system autonomously decides whether to call a retrieval agent and which collection to query, rather than systematically retrieving on every input.

This is grounded in two complementary ideas from the NLP literature:

- **Self-Consistency** (Wang et al., 2022): sampling multiple answers from an LLM and taking the majority is more reliable than greedy decoding. Agreement across samples correlates with answer correctness.
- **Selective RAG / Active RAG**: triggering retrieval only when necessary, rather than unconditionally, improves efficiency without sacrificing accuracy.

## Architecture

```
User Query
    │
    ▼
┌─────────────────────────────────┐
│           ROUTER (main.py)      │
│                                 │
│  1. Query LLM × 3  (temp=0.7)   │
│  2. Embed answers               │
│  3. Pairwise cosine similarity  │
│  4. Avg score ──► threshold ?   │
└─────────────────────────────────┘
         │                  │
    score ≥ 0.9         score < 0.9
  (high confidence)   (low confidence)
         │                  │
         ▼                  ▼
   Direct Answer      ┌───────────────────────┐
                      │    RAG PIPELINE        │
                      │      (rag.py)          │
                      │                        │
                      │  1. Encode query       │
                      │  2. FAISS search top-k │
                      │  3. Build context      │
                      │  4. Grounded LLM call  │
                      └───────────────────────┘
                               │
                               ▼
                       Grounded Answer
                       (with citations)
```

The FAISS index is built **offline** by `indexer.py` and loaded at startup by `rag.py`.

## Technical Choices

### Embedding Model: `all-MiniLM-L6-v2`

A **bi-encoder** from the Sentence Transformers library. It uses **mean pooling** over all token embeddings (weighted by the attention mask) to produce a single 384-dimensional dense vector per input. This captures semantic meaning across the full input sequence, enabling similarity search that goes beyond keyword overlap. Note that the model has a **maximum sequence length of 256 word pieces** — any input beyond that is silently truncated.

The same model is used in two places:
1. **Indexing/retrieval** (in `rag.py` and `indexer.py`): to encode document chunks and queries into the same vector space.
2. **Consistency scoring** (in `main.py`): to embed the LLM's multiple answers and measure their pairwise semantic agreement.

Using a single shared model for both tasks is a deliberate simplification. A cross-encoder would be more accurate for re-ranking but is far too slow for retrieval over tens of thousands of chunks.

### FAISS with Inner Product + L2 Normalization

`faiss.IndexFlatIP` (Inner Product) with L2-normalized vectors is mathematically equivalent to cosine similarity search. Vectors are normalized at both indexing time (`indexer.py:64`) and query time (`rag.py:28`) with `faiss.normalize_L2`.

`IndexFlatIP` performs **exact exhaustive search** — no approximation. This is appropriate at the current scale (~20,000 documents) and avoids the complexity of approximate indexes like IVF or HNSW. At larger scale, `IndexIVFFlat` or `IndexHNSWFlat` would be better trade-offs.

### Chunking Strategy

Documents are split into **200-word chunks with a 30-word overlap**. The overlap ensures that context at chunk boundaries is not lost. Chunks shorter than 20 words are discarded as noise.

Word-level chunking (rather than character-level) is used because it maps more intuitively to semantic content density. The 200-word size is a practical sweet spot: long enough to carry sufficient context for embedding, short enough that the retrieved passage remains targeted.

### Knowledge Base: Google Natural Questions

The index is built from the first 20,000 examples of the [Natural Questions](https://ai.google.com/research/NaturalQuestions) dataset, which contains real Google Search queries paired with Wikipedia documents. Using a QA-oriented corpus ensures the knowledge base is relevant to the kinds of factual questions users are likely to ask.

### Consistency Gate Threshold

The threshold is set to **0.9**. A score of 1.0 means the three answers are semantically identical; a score near 0 means they are completely different. At 0.9, the gate tolerates minor phrasing variation while catching genuine uncertainty (diverging facts, hallucinations, hedging). This value was selected empirically and can be tuned via the `CONSISTENCY_THRESHOLD` constant in `main.py`.

### LLM: Mistral Small

`mistral-small-latest` is used for both the consistency sampling and the grounded generation step. It offers a good accuracy/cost trade-off. The temperature is set to **0.7** during consistency sampling to introduce controlled variability — a temperature of 0 would always return the same answer, making the consistency check meaningless.

## Evaluation

The IR component is evaluated in [`evaluation_ir.ipynb`](evaluation_ir.ipynb) using **Mean Average Precision at rank 20 (MAP@20)**.

| Metric   | Value |
|----------|-------|
| MAP@20   | **0.58** |
| Questions | 201  |
| K (top-k) | 20  |

Ground truth is determined by URL matching: a retrieved chunk is considered relevant if its source URL matches the document URL associated with the question in the Natural Questions dataset.

A MAP@20 of 0.58 is a solid baseline for exact search with a lightweight bi-encoder, especially given that the index only covers 20,000 documents out of the full dataset.

- A [Mistral AI API key](https://console.mistral.ai/)

1. **Clone the repository**
   ```bash
   git clone https://github.com/yourusername/Consistency-Gated-RAG.git
   cd Consistency-Gated-RAG
   ```

2. **Install dependencies**
   ```bash
   pip install mistralai sentence-transformers faiss-cpu datasets numpy python-dotenv beautifulsoup4 tqdm
   ```

3. **Configure your API key**

   Create a `.env` file at the project root:
   ```env
   MISTRAL_API_KEY=your_api_key_here
   ```

## Usage

### Step 1 — Build the knowledge base (offline, run once)

This downloads the Natural Questions dataset, processes 20,000 documents, and writes `my_rag_db.index` and `my_rag_db.json` to disk.

```bash
python indexer.py
```

> **Note:** Processing 20,000 documents takes several minutes and requires ~2 GB of disk space. Adjust `NB_ROWS` in `indexer.py` to index fewer documents during development.

### Step 2 — Run the assistant

```bash
python main.py
```

The system will prompt for questions interactively. For each query it prints the consistency score and indicates whether the answer came directly from the model or from the RAG pipeline.

```
=== ASSISTANT INTELLIGENT (CONSISTENCY-GATED RAG) ===
Seuil de confiance : 0.9
Tape 'q' pour quitter

 Votre question : What is the speed of light?
[ROUTER] Score de confiance: 0.97
VALIDE : Le modele connait la reponse !

 Reponse:
The speed of light in a vacuum is approximately 299,792,458 metres per second...

 Votre question : Who won the 1987 Ecuadorian elections?
[ROUTER] Score de confiance: 0.61
>>> DOUTE (Score < 0.9): Activation du RAG.
Recherche dans la base de documents...

 Reponse verifiee (RAG) :
...
```

### Step 3 — (Optional) Evaluate the IR component

Open and run [`evaluation_ir.ipynb`](evaluation_ir.ipynb) to compute MAP@20 on 201 questions from Natural Questions.

## Limitations & Future Work

- **No re-ranker**: retrieved chunks are ordered by cosine similarity with no cross-encoder re-ranking step. Adding a cross-encoder on the top-k results would improve precision.
- **Exact FAISS search**: `IndexFlatIP` is O(n) in the number of vectors. Switching to `IndexIVFFlat` or `IndexHNSWFlat` would be necessary for larger corpora.
- **Fixed threshold**: the 0.9 consistency threshold is hand-tuned. A learned or adaptive threshold (e.g. calibrated on a held-out set) would be more robust.
- **No answer fusion**: when RAG is triggered, the original direct answers are discarded. A future version could fuse the direct and grounded answers.
- **Knowledge base scope**: only 20,000 NQ documents are indexed. Scaling to the full dataset or a broader corpus would significantly improve recall.
